### 1. Chunked accumulation
Mock `api.tableFields` so the first call resolves with `{ fields: [chunkA fields], partial: true, next_after: "cursor1" }` and the second call resolves with `{ fields: [chunkB fields], partial: false }`. Use `mockImplementationOnce` twice, or inspect the `after` option in the opts arg to decide which chunk to return.

Pick field names that are visibly rendered as leaf rows (e.g. depth 1, `kind: "scalar"`, with a `column` name). A simple shape that renders:

    { depth: 1, name: "alpha", type: "VARCHAR", kind: "scalar", column: "alpha",
      access: { first: '"alpha"', sel: '"alpha"', unnests: [] } }

Assert that fields from BOTH chunks are visible in the DOM via `await screen.findByText("alpha")` and `await screen.findByText("beta")` (names from the two chunks). Also assert `api.tableFields` was called at least twice.

### 2. Abort on source switch
Build a `tables` prop with TWO nested tables (two sources). Mock `api.tableFields` so that for the FIRST source it returns a promise that resolves slowly (e.g. `new Promise(r => setTimeout(() => r({ fields: [...first-source fields...], partial: false }), 100))`) and for the SECOND source it resolves immediately with different field names. Render FE with the first source auto-picked (or `fireEvent.change` the select to pick source 1), then immediately switch to source 2 by changing the select value. Assert that field names unique to source 1 never appear (`expect(screen.queryByText(...)).toBeNull()`), while source 2's fields do appear.

Note on auto-pick: `FieldExplorer` auto-selects the only source when `sources.length === 1`. With two sources neither is auto-picked, so drive the `<select title="Pick a loaded table to explore">` via `fireEvent.change(select, { target: { value: srcKey } })` where `srcKey` is `${engine}\u0000${table}`.

### 3. Empty field list
Mock `api.tableFields` to resolve `{ fields: [], partial: false }`. Render FE. Assert:
- The component mounts without throwing (no act warnings fine).
- No field rows render — `screen.queryByTestId("fx-caret-json")` is null, and the field list area is empty.
- The selection bar still reads something like "Check fields to combine" (that testid is `fx-sel-bar` per existing tests). Use that as the "did not crash and shows empty state" signal.

### 4. dataEpoch refresh
Render FE with `dataEpoch={1}`. Wait for the initial `tableFields` call to settle (`await waitFor(() => expect(api.tableFields).toHaveBeenCalled())`). Record the call count. Then `rerender(<FieldExplorer open onClose={...} tables={nestedTable()} dataEpoch={2} onToast={...} />)`. Assert `api.tableFields` was called again after rerender (call count strictly greater). Pass the SAME `tables` reference both renders (or an equal shape) so the extra call is attributable to the epoch bump, not a tables identity change.

### 5. Cancelled discovery
Mock `api.tableFields` to resolve `{ fields: [one visible field row], cancelled: true, partial: false }`. Render FE. Assert the single field name is visible (`await screen.findByText(...)`) and the component is NOT in a perpetual loading state — specifically, wait for `busy` to clear. The component does not expose a specific "loading" testid in the audit scope; a sufficient proxy is: `await waitFor(() => expect(api.tableFields).toHaveBeenCalledTimes(1))` and then confirm no second call is issued (no further pagination because `cancelled: true` breaks the loop). You can wait a short tick with `await new Promise(r => setTimeout(r, 50))` after the first resolve and then assert `expect(api.tableFields).toHaveBeenCalledTimes(1)`.

## Component facts you can rely on
`FieldExplorer.tsx` discovery loop (lines ~296–346):

    while (!ctrl.signal.aborted && gen === fieldsFetchGen.current && key === srcKeyRef.current && openRef.current) {
      const r = await api.tableFields(engine, table, ctrl.signal, { after, query_id, budget_sec: 1.0 });
      // bail if gen/srcKey/aborted/closed
      const chunk = (r.fields || []);
      acc = after ? acc.concat(chunk) : chunk;
      setFields(acc);
      if (r.cancelled || !r.partial || !r.next_after) break;
      after = r.next_after;
    }

dataEpoch effect (lines ~382–390): when `[srcKey, open, dataEpoch]` changes and `open && src`, it calls `reloadFields(...)` which bumps `fieldsFetchGen` and schedules a new `tableFields` call via `runAfterPaint`.

Source select title: `"Pick a loaded table to explore"`. srcKey format: `${engine}\u0000${table}`.
